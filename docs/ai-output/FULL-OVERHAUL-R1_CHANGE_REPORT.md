## Reviewed with no defect found (evidence)

- **Task movement inherited through private trip passengers:** `GET /events/:id/tasks` masks pickup/destination when either `Task.guestId` or any trip passenger is private to the viewer. Telemetry trip DTOs withhold driver, vehicle, origin, destination, route, in-zone and ETA. ETA refresh refuses protected trips before calling routing.
- **Historical message text and participant names:** `loadMessageRedactions` and `redactMessagePayload` are applied to inbox items and to `/messages` lists, threads and replies for organization events, using current grants. Grants count only while the viewer is an active member. Legacy `/notifications` and other legacy routes pass through `legacyWorkspaceBoundary`, which replaces masked-guest values and omits organization-event references.
- **Current grants and expired/revoked membership:** `loadEventAccess` accepts only ACTIVE memberships. Inbox, thread, reply, read and unread paths re-evaluate per request. Socket `event:` rooms refuse organization events (`canReadEvent`), workspace drivers' frames are not broadcast, and pending applicants and suppliers cannot connect.
- **Pending applicants and fresh activation sessions:** the `onboardingPending` claim restricts REST to `/workspace/onboarding*` and `/auth/me`. Login and refresh re-read `onboardingPending` and role from the database. Activation clears the flag atomically, and the client refreshes the session explicitly.
- **Six dispatch flows:** the sender's role comes from stored membership. Recipients must be ACTIVE event members with VIEW, the right role and receiving enabled. Guest-to-captain requires a stored trip or task link. Emergency requires an available captain on shift and an available supervisor (otherwise 409, with nothing written). The task, alert, notifications, record and audit are written in one transaction.
- **Captain shift/assignment:** emergency dispatch and task assignment require an ON_SHIFT, available, current shift when the captain has any shifts.
- **UI/API shapes:** dispatch recipients and message contacts return `{id,…}`, and the UI posts those ids. Task assignment and messaging policy use `member.user.id` (user id), not the membership id. Datetimes are sent as `…+03:00` and converted to ISO. Resource keys include the token and scope, and old requests are aborted. Retry ids are stable until success.
- **No legacy or synthetic rosters in organization scope:** new workspace components import no demo, mock or seed modules. Field apps mount the previous personal views only on request.
- **Providers:** the codebase has no Google references. OSRM is used only from server-configured `OSRM_BASE_URL` (HTTPS or loopback, 4 s abort, bounded body) and otherwise falls back to a labelled approximation or "unavailable". AI planning sends anonymous counts only (6 s timeout, concurrency and window caps) and falls back deterministically, and explicit approval is still required. Weather and flight data are labelled unavailable or stored manual records.

## Unresolved issues and limitations (not fixed)

None of these is Critical or High. Codex or the owner should decide whether to act on them.

1. ~~Medium: privacy-group race.~~ Fixed in R2 (R2-5 above).
2. **Low/design:** a captain with **no** shift records is eligible for emergency dispatch and assignment. The M6 report says "off-shift captains are ineligible", but a captain with no shifts is not off-shift. Making shifts mandatory is a product decision.
3. **Low:** an assigned captain or responsible user may move a task to CANCELLED, and a captain may cancel its trip (`statusTransitions` and `TRIP_TRANSITIONS`). Restricting this is a product decision.
4. **Low:** the Event overview form re-submits every scope field. Times are minute-precision, so an event stored with seconds would record a spurious `startAt`/`endAt` scope change and notify vendors on an unrelated edit.
5. **Low:** `GET /events/:id/members` shows `workScope` and permissions of all members to every non-client member, including captains and coordinators.
6. **Operational:** `legacyWorkspaceBoundary` loads organization-wide id sets on every legacy request (capped at 10,000 per set, otherwise 503). It is correct, but its cost grows with data.
7. Rendering, browser, PostgreSQL-concurrency and live-provider behaviour were not exercised by Claude. The new tests use the serialized in-memory Prisma double. The real row-lock ordering in F2 and F3 still needs Codex's PostgreSQL verification.
